# Rubric 权威模式切换方案（尚未具备启用条件）

当前配置 innovationMode 默认 shadow。authoritative 可被配置解析，但 Host 启动立即明确拒绝，不能静默回退或视为已生效。旧 0–100 分、70 门槛、重试和 DAG 仍决定新任务。没有从旧分到 Rubric 的换算。

解锁必须另行实现和审查：每个目标领域至少三位适当背景且独立的真实专家；独立提交、原文证据核对和分歧协调；在保留样本之外验证经校准的决策规则、错误放行风险与适用边界。专家数量或一致率本身不证明效度。没有通用固定 Rubric 门槛。

未来权威执行契约：Rubric v1.7.0 或用户明确指定后续版本为新候选唯一评分来源；旧分只作历史与对照。complete 必须匹配已校准领域/版本/比较范围和决策规则才可自动前进。provisional 展示争议并进入人工确认。insufficient/null 补证或人工复核，不视为通过或零分。确认与人工例外均持久审计，收费推理另有授权预算。

切换前后须用同一证据集验证 accepted/review-required/needs-evidence 三条路径，取消、超时、离线和重启不能绕过门禁。拒绝缺失/过期校准、错领域/错版本与未经审查规则。research v1 历史只读展示，不重算、不迁移；新增策略与审计用独立版本记录。回滚只影响将来新运行，保留当时策略身份。当前尚未实现这套权威决策执行器，不能开启唯一评分。

数据边界：controller 内仍全局串行，保护多个 Session 对同一 JSON domain 的写入；不宣称不同 Session 已并行化。显式 dataDirectory 现在有单 Host 写入租约。正常关闭后释放；崩溃残留须人工核实记录 PID 已退出后清理，不自动抢锁。默认官方 storageDomain 沿用官方 Host 所有权，不能将同一 profile 同时共享给多 Host。

阶段超时默认 300000ms，信号传到网络/模型，评审成功项逐项保存到 research_review v1。主动重试复用相同 session/node/角色/提示哈希的成功项；失败、取消或遗留 running 项可能再次调用，须由用户明确重试阶段。进程在模型已计费、结果尚未持久化之间崩溃，仍存在无法做到 exactly-once 的窗口。不得把多模型角色评审当作独立专家校准。

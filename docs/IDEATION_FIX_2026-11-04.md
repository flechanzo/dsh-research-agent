# 创新点与 Rubric 修复验证（2026-11-04）

## 根因及修复

1. 目标任务提取把历史标题中的“待确认”误当作尚未确认的范围，多个字段持续生成占位语句；旧界面仍允许确认，Rubric 因此在调用前退出。改为使用节点实际确认状态、允许明确不限模型/数据集/预算，并在界面和后端共同校验范围。
2. 文献检索直接截断中文长句，arXiv 查询编码和 OpenReview 搜索入口不正确，DoRA 任务混入天体物理论文。增加使用当前所选模型的英文关键词规划，修正查询编码、相关性排序及 OpenReview 搜索接口。
3. 默认只读取 PDF 前 12 页，用户的 DoRA.pdf 有 23 页，无法满足 Rubric 全文证据要求。默认上限调整为 30 页，Rubric 重新读取独立页数预算内的原文。
4. 创新阶段超时后丢失已完成候选和评价。增加与任务、输入及模型路由绑定的检查点，重试复用有效结果，展示候选及 Rubric 阶段进度。普通阶段默认 15 分钟；Rubric 独立预算默认 10 分钟、单阶段 2 分钟，仍保留超时与证据门槛。
5. 严格 JSON 解析兼容单一 Markdown JSON 代码块，不从任意解释性文本中猜取结果。
6. 真实模型曾把上传的 DoRA 论文贡献作为评分对象。明确候选是唯一被评对象，贡献必须逐字引用候选，背景论文仅作先例。
7. 原文地址失败时，使用 OpenAlex 同一 work 提供的出版方备用地址；保留失败获取记录，不按相似标题替换论文。
8. 未确认固定模型版本时，将恢复身份绑定 Host、提供方与实际模型路由。源码、Host 或模型改变时新建审计，保留旧结果；一致时复用有效检查点。
9. rc.3 真实运行正确提取候选，并取得三篇完整原文；另一篇来源停留于摘要页且公开下载返回 403。修复同源 Digital Commons 下载链接识别，并把获取失败交给原文审查器判断其决定性；只有已有原文支持的非关键排除才允许继续，未解释的失败来源仍保持 null。首轮查新增加论文首页标题信息，要求按真实原论文标题建立基线。
10. rc.4 真实确认请求持续约 5 分钟后，界面报 `research/confirm ... Failed to fetch`，Host 随后取消，和已配置的阶段时间预算不符。将耗时上传、确认、拒绝重试、Rubric 恢复切换到官方 Remote 流式载体，定期发送进度；仍联动用户取消、界面生命周期和 Host 时间预算，流未返回最终结果不能视为成功。
11. rc.5 真实审查器只得到贡献摘录，无法比对完整候选；合法的候选对照引用也被当作伪造先例拒绝。向审查器提供完整候选，允许候选与实际先例原文混合引用，但仍强制要求原文证据；最近先例 ID 用实际取得的来源枚举约束。
12. 第一、二轮发现关键缺口时过早退出，未能进入后续补搜。现在将缺口逐项传递，只有明确的原文证据解决记录才能消除；第三轮仍有关键缺口时保持 null。跨领域检索噪声可按相关性筛除，技术近邻仍须原文比较。JSON/Schema 或主流程检索词格式失败允许一次有界修复，不对网络失败无限重试。
13. rc.6 真实审查识别出 BoRA 的 PDF 备用地址，以及候选原文已引用的两个 OpenReview 链接，但来源校验仅检查主 URL，误报“替代先例不是实际发现的来源”。rc.7 接受索引实际提供的备用地址，将候选中的精确链接登记为待核验线索，保持未知链接拒绝与真实全文门槛。跨轮缺口按同一来源登记，避免从 PDF 切回摘要地址后无法消除已解决缺口。
14. 候选引用可能没有索引发表日期。仅对比较当日真实公开取得的全文允许用获取记录证明“当时可得”，明确保留发表日期未知，并将结果最多标为 provisional；不反推发表日期，历史比较仍要求日期与版本证据。若该日期不确定性影响科学定类，审查器仍必须保留关键缺口。
15. rc.7 真实模型将 BoRA 第 5 页的一段实际原文误标为第 4 页，全文引用验证通过但页码验证阻断。rc.8 仅在引用逐字存在且唯一属于另一已登记页/章节时纠正位置；审计阶段 `citation-location-resolver` 记录原报位置、实际位置及引文哈希。不修改引文、来源或结论；不存在的页码、多个候选位置和伪造引文仍拒绝。
16. rc.8 又暴露 PDF 断词差异：模型引用 `magni- tude`，对应原文为 `magnitude`。rc.9 仅归一字母间的断行连字符与空白，并保留原始引文和审计标记；不容忍实质单词差异。所有阶段在保存成功前校验引用，JSON/Schema 或引用错误共享一次有界修复机会；修复仍不符原文则失败，模型未完成、网络失败或科学缺口不进入这一格式重试。
17. rc.9 第一轮已通过一次有界引用修复，但第二轮计划的候选文献线索被误当作先例原文拒绝。rc.10 向计划器提供完整候选，允许候选辅助引用，同时强制至少一项前轮实际取得的原始来源引用；仅候选、未在前轮读取的背景来源仍拒绝。新增三种对应回归用例。
18. rc.10 实测 DoRA 基线查询已成功返回原始来源，但检查点保存遇到 Windows `EPERM rename`，被外层误当成检索失败后继续，导致候选列表漏掉 DoRA。rc.11 对此类本地原子替换失败最多重试三次（50/150/400 ms），不重复外部请求；其他存储错误不重试。无法持久化时明确停止，不把存储失败吞为网络缺口。新增暂时占用、持续占用、其他存储故障及检索保存失败的回归测试。
19. rc.11 的真实第一、二轮通过后，第三轮计划被模型误标为 adversarial。rc.12 将策略按轮次固定，并在输出 Schema 中仅接受该轮的唯一值，错误走同一有界修复；不会因模型选择错误标签直接丢失整条流程。
20. 已成功的格式修复在恢复时原先要重做失败的原请求，可能使后续检查点序号偏移。现在记录验证失败类型，存在已成功修复时重放本地校验失败，随后仍按输入/输出哈希及证据校验复用修复结果，避免重新调用原失败请求。
21. 隔离 Desktop 暴露首次评分因确认前尚无 target_task 而漏记完整模型身份；现从首次操作开始统一记录模型路由。还修复下一阶段预检查失败时误将上一成功模型结果作废的问题。前轮的网络诊断保留在完整审计中，不重复进入科学提示；实际来源、关键缺口和原文失败说明仍保留，纯限流措辞变化不再触发模型重算。

原有 70 分门槛、重复性判断、Rubric 三轮查新、全文引用核验与 Shadow 模式保持不变；不把证据不足的 null 改成虚构分数。

本轮只准备环境和运行本地 Mock。真实模型推理由你亲自在官方 Desktop 发起。当前真实调用闸门锁定，价格、版本状态和新预算必须由你确认；不会沿用此前的费用授权。Rubric 保持 Shadow，评分条件不满足时保持 `S=null`。

## 第一次配置和手动开始

1. 当前窗口右侧已打开“自动科研流程”，停在上传论文之前。左下角账号菜单 → 设置 → 模型，使用官方界面配置你要测试的提供商和模型。原生模型选择器在输入框下方；本轮没有替你填入 API Key。
2. 记录实际 Provider ID 和 Model ID。Provider ID 不是显示名称；可在原生“打开配置文件”中核对提供商条目的 `id` 和模型条目的 `id`，不要把密钥填到测试确认表。
3. 用“保存并关闭”退出隔离 Desktop。运行“确认测试条件”，核对不可变模型版本、价格状态、费用预算说明和本次调用预算，然后由你勾选确认。版本或价格未知时要明确填写未知。确认表不会调用模型。
4. 重新运行“启动隔离Desktop”。在原生模型选择器中选择与确认表精确匹配的路由。在新会话的“标准模式”菜单选择“自动科研”；右侧科研面板已打开时，可直接使用面板。
5. 由你点击“上传论文并开始”，选择下述公开 DoRA PDF。上传后会触发摘要等模型阶段，请只在条件核对完成后操作。后续摘要、计划、评审和 Shadow 审计按界面逐项人工确认。
6. 打开“调用统计”，观察调用数、已知/未知 Token、提示字符、耗时、预算、错误及 Rubric 阶段。不要为了获得数值分数跳过三轮查新或证据核验。

官方原生账号组件可能显示系统已有的登录态。Profile、工作区隔离不等于服务商账号或账单隔离；本轮没有执行登录、退出、充值或修改正式模型配置。使用哪一个真实计费账号，由你在原生界面核对。

## 默认预算与统计边界

默认累计准入上限为 24 次原生模型 dispatch、100 万序列化提示字符、每次最多 4096 输出 Token、从第一次真实请求起 300 秒。失败和恢复调用也计数；已计费但崩溃时未收到 usage 的请求不会补记为零费用。Provider 自动重试插件已在隔离 Profile 禁用，服务商内部不可见重试无法统计。

Rubric 另有独立预算：总计 300 秒、单阶段 60 秒、最多 24 次模型调用、30 次网络操作、100 万提示字符、一个候选、PDF 最多 30 页、OCR 为 0。外层闸门还统计摘要、计划等非 Rubric 原生调用，所以可能先于 Rubric 预算耗尽。

总时间闸门控制后续请求准入，包含人工等待时间，不会保证服务商在 300 秒整停止正在生成的响应。当前请求使用原生停止按钮；Rubric 另执行阶段超时。**费用始终显示未知，本地没有可靠的人民币金额硬限额。** 如需金额硬限额，先在服务商后台设置；不要把 Token 或字符上限当作准确费用。

统计不保存提示正文，只记输入哈希、字符数、路由、调用状态、已报告 Token 和延迟。缺少 usage 的 Token 为 `null`；同时列出已知部分，不把未知当零。检查点和科研结果保留实际公开证据及有效输出。

## 暂停、恢复与结束

- 暂停当前任务：在 Desktop 点击停止/取消。需阻止后续请求时，再运行“暂停后续调用”。已经完成且有效的检查点保留；不要强杀进程代替正常暂停。
- 恢复科研评审：回到原会话和原科研项目，使用界面的失败评审恢复操作。恢复 Rubric：展开 Shadow 候选对照，查看失败原因和有效阶段，使用“配置新预算并恢复 Rubric”。外层闸门也必须仍有额度；已锁定或耗尽时，先关闭 Desktop，再由你确认新预算并重启。
- 修改 target task、候选、Rubric、证据或模型输入会使不匹配阶段失效。只有核实不可变模型版本后才允许跨重启复用模型输出；版本未知会保守拒绝跨 Host 复用。跨崩溃无法承诺模型调用 exactly-once，存在重复计费可能。
- 测试结束运行“保存并关闭”。证据保存在隔离 root 的 `evidence\shareable\closed-<时间戳>`，包含脱敏元数据、检查点、科研结果和允许保存的截图。设置/密码对话框或检测到凭据时跳过截图。分享前请人工复核截图和结果；不要分享整个 `home`、`electron-user` 或凭据目录。
- 普通关闭窗口也会尽力归档；异常断电后可能没有最终截图，检查点和调用账本仍保留。没有自动清理正式目录的步骤。
